Scope choice for the V4.4 spec

A

Reports-first Quality Analytics

Extend the existing Reports page with quality metrics, trends, failure-pattern drill-down, and project/workflow/task-type grouping. This is the safest V4.4 slice.

B

Quality API first

Build the orchestrator/shared-contract aggregation model first, then add only a minimal UI. This is stronger architecturally but less product-visible.

C

Insights-to-recommendations bridge

Start turning repeated quality patterns into workflow/skills recommendations. Useful, but it overlaps V4.5 and may make V4.4 too wide.
