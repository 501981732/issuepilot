Second Design Section: Architecture / Data Flow

V4.5 should add a small improvements module in orchestrator, not expand the V4.4 quality aggregator into a policy engine. V4.4 remains responsible for metrics and failure-pattern classification; V4.5 consumes those facts and creates durable recommendation records.

The first version should be deterministic-first: map repeated missing-evidence, missing-tests, environment-issue, permission-issue, review-rework, and unclear-requirements patterns to known improvement templates. Each recommendation links back to concrete drilldown items so the operator can audit why it exists.
