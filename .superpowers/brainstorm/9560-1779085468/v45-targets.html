V4.5 Recommendation Types / Patch Targets

First version should recommend changes to execution guidance, not runtime state machines.

In Scope

Workflow front matter

CI policy, retention hints, max attempts, sandbox warnings, project workflow metadata.

Prompt template

Missing evidence instructions, required validation wording, review feedback handling.

Project rules

Repo-local AGENTS / project facts / acceptance discipline suggestions.

Skill instructions

Advice to update or create skills, but only as patch preview.

Recommended V4.5 Target Set

High leverage and reviewable. These are the places repeated quality problems usually come from.

Out of Scope

No auto label changes

Do not alter workflow labels or issue state transitions.

No secret edits

Do not write tokens, credentials, or private env values.

No production policy

Do not change RBAC, budgets, merge automation, or worker scheduling.

No direct commit

Patch preview only; applying remains human-gated.

Hard Safety Boundary

V4.5 improves process guidance without becoming a self-modifying control plane.

Third Design Section: Recommendation Types

Each recommendation should have a target.kind: workflow_front_matter, prompt_template, project_rules, or skill_instruction. It should also carry problemPattern, evidenceRefs, suggestedChange, patchPreview, confidence, risk, and status.

V4.5 should not modify runtime state machines, labels, credentials, production policies, or merge behavior. Those are either existing orchestrator contracts or V3 production-platform concerns.
